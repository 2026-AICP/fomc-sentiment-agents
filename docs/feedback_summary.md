### 알림 기능 — 설계 완료

`docs/notification_design.md`. 지금 알림을 보내는 게 아니라 **기준을 정하는 단계**다.

- **이메일.** 웹푸시는 미룸 — FOMC 발표가 KST 새벽 3~4시라 PC는 꺼져 있고 iOS는
  홈 화면 추가가 필요하다. **가장 필요할 때 가장 안 닿는다**
- **🔴 경고 기본**, 구독자가 ⚠️까지로 변경 가능 (⚠️ 전부는 이틀에 한 번이라 기각)
- **정정 알림은 등급이 실제로 바뀐 경우만** — 질문 6 속보치/확정판과 직결
- **구독자 정보는 리포에 커밋 안 함** — 공개 저장소, 이력 영구

**적중 기준을 미리 못 박았다** (`docs/alert_hit_thresholds.md`). 나중에 결과를 보고
기준을 정하면 유리한 쪽으로 맞추게 되므로, 6,701 거래일로 계산해 고정했다.

```
알림 후 5거래일 안에  |S&P| > 3.74%  또는  |ΔVIX| > 4.76pt  → 적중
아무 날이나 찍었을 때의 적중률 = 14.5%
```

**여기서 오류를 하나 잡았다.** 초안은 "상위 10% 기준이니 무작위도 10%"라고 적었는데
조건이 **"또는"** 이라 실제로는 14.5%다. 안 고쳤으면 **성과를 1.45배 부풀릴 뻔했다.**
같은 오류가 검정력 계산에도 옮겨가서, **유의성 확보에 1년이 아니라 2.5년**이 필요하다.
→ **올해 보고서에는 "적중률 X%"를 쓸 수 없고, "기준을 사전 등록했다"까지만 쓸 수 있다.**

**남은 것**: 구현 전부 (도메인 → Resend → Worker → 구독 UI → Notifier). 단계별 승인.

### ★ 질문 5 를 "완료"에서 "부분 완료"로 내렸다

조교님 지적 원문은 이렇다.

> 기사 6건(**CI가 0을 크게 걸침**)인 날에도 "주의"가 발동했다

**증상이 두 개인데 하나만 막고 있었다.** 게이트는 기사 수와 **CI 폭**을 보지만,
**0 을 걸치는지는 검사하지 않는다.**

🔴 경고와 부호전환 신호는 지수의 **부호**로 판정한다. 구간이 0 을 걸치면 그 부호를
말할 수 없다. 표본에 하나뿐인 🔴 이 정확히 여기 해당한다.

```
2026-07-17  🔴 경고   지수 +0.058   95% CI  -0.170 ~ +0.287
   "뉴스는 긍정인데 시장은 -1.01%" 가 논리인데, 뉴스가 긍정이었는지를 말할 수 없다.
   음수였다면 뉴스도 시장도 같이 나빴다는 뜻이고, 괴리는 애초에 없다.
   CI 폭 0.457 은 상한 0.60 을 여유 있게 통과한다.
```

56일 중 **44일(79%)이 부호 불명**이고, 부호 확정 + 기사 15건 이상은 **5일**뿐이다.
**`ci_max` 를 조인다고 잡히는 문제가 아니다 — 검사 항목이 빠져 있다.**

### 게이트 임계값(15건·0.60)에 근거가 없다

찾아보니 **2026-07-03 파일 생성 커밋에서 데이터 없이 찍은 값**이다. 그날은 뉴스 지수
첫날이라 볼 분포가 없었다. 코드에도 "잠정"이라고 적혀 있다. 원래 데이터 쌓이면
보정하기로 했는데 8월 수집이 깨져 미뤄둔 상태였다.

그래서 대신 **"값을 바꿔도 결론이 안 바뀌는지"** 를 확인했다(`docs/gate_sensitivity.md`).
θ 보정 때 쓴 것과 같은 논법이다. **결과는 반반이다.**

| | 판정 |
|---|---|
| `min_articles=15` | **방어 가능.** 8~30 으로 흔들어도 등급 변동 최대 5일/56일(9%) |
| `ci_max=0.60` | **방어 불가.** 0.30 이면 56일 전부 관망. 유일한 🔴 을 뒤집는다 |

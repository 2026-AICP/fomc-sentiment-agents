# VIX 대체 경제지표 선정 — 통합 가중치 검증 설계

> 작성일: 2026-08-09 · 상태: 설계 확정 (구현 전)
> 지도교수 피드백 "VIX 대신 다른 경제지표 사용 고려" 대응

---

## 1. 배경 — 왜 필요한가

`analysis/headline.py` 의 Fed·News 50:50 결합은 **VIX 상관 하나로 정당화**되어 있다.

| | VIX 상관 (2000-02~2021-05, 256개월) |
|---|---|
| Fed 단독 | -0.436 |
| News 단독 | -0.386 |
| **통합 (50:50)** | **-0.534** |

지도교수 피드백으로 VIX 사용이 보류되면서 **이 근거가 비었다.** 가중치 자체는 "50:50 유지" 지시로 살아 있으나, "왜 두 축을 합치는 게 나은가"를 뒷받침하는 실증이 사라진 상태다.

보류 사유는 전달받지 못했다. 가능한 해석이 셋인데 어느 쪽인지 모른다:

- **A. VIX 는 변동성 지수라 '경제지표'가 아니다** → 거시지표로 교체해야
- **B. 주식시장 중심이라 통화정책과 멀다** → 금리·정책기대 지표로 교체해야
- **C. 순환논리** → 지표 교체만으로는 부족

→ **세 해석 어느 쪽이든 통과하는 설계**로 간다. 성격이 다른 지표 여러 개에 같은 검증을 반복해, 결론이 지표 전반에서 유지되는지를 본다.

### 순환논리(해석 C)에 대한 답

가중치 50:50 은 **지도교수가 사전에 고정한 값**이지 데이터로 적합한 파라미터가 아니다. "VIX 상관이 최대가 되도록 가중치를 골랐다"가 아니라 "고정된 50:50 이 각 축 단독보다 나은가"를 검정하는 구조이므로 순환논리가 아니다. 이 논리를 결과 문서에 명시한다.

(참고: `docs/news_fed_index.md` 에는 70:30·30:70 변형의 VIX 상관도 함께 실려 있으나, `build_headline_norm.py` 코드가 실제로 계산·저장하는 것은 50:50 하나뿐이다. `headline.py` 기본값도 `w_fed=0.5` 고정이다. 변형 수치는 감도 확인 기록이지 가중치 탐색의 결과가 아니다.)

## 2. 범위

**이 문서가 다루는 것**: 통합 가중치의 검증 기준이 될 경제지표 선정과 검증 절차 설계.

**다루지 않는 것** (다른 팀원 담당):

| 항목 | 담당 |
|---|---|
| 감성지수로 무엇을 예측할 수 있는지 (예측 대상 탐색) | 별도 팀원 |
| 설명력(R²)·회귀·Newey-West 등 계량 확장 | 별도 팀원 |
| 가중치 해석과 스토리텔링 | 별도 팀원 |
| 관련 논문 서치 | 별도 팀원 |

이 설계의 산출물(지표별 상관표)은 "가중치+스토리텔링" 담당자가 그대로 받아 쓸 수 있는 형태로 만든다.

## 3. 지표 패널

선정 기준은 **연준의 목표와 도구**다. "왜 이 지표냐"에 대한 답이 임의 선택이 아니라 통화정책 이론이 되도록 한다.

전 계열 FRED 공개 CSV 로 **API 키 없이** 수집된다 (`collect_market.py` 의 `FRED_CSV` 패턴 그대로). 크롤링이 아니라 공개 데이터 파일 다운로드다. 아래 시작 시점은 2026-08-09 실제 조회로 확인했다.

- **신용조정 (재할인창구)**: 위기 국면에만 활성화되는 간헐적 도구라 연속 시계열로 존재하지 않는다. 2008·2020 같은 특정 시점 이벤트 분석에는 쓸 수 있으나 256개월 상관에는 부적합하다.

## 4. 가설 사전 등록

돌리기 전에 확정한다. 나온 부호에 맞춰 사후에 해석을 지어내지 않기 위해서다.

**전제**: FinBERT 는 금융 감성(긍정/부정) 도구이지 정책 스탠스(hawk/dove) 도구가 아니다. 이 구분이 부호 예측을 갈라놓는다.

| 가설 | 내용 | 예측 |
|---|---|---|
| **H1 경기인식** | 톤↑ = 연준이 경제를 낙관 | `INDPRO` 양(+), `UNRATE` 음(−), `NFCI` 음(−) |
| **H2 정책반응** | 낙관 → 긴축 여력 | `DGS2` 양(+), `DFF` 양(+), `WALCL` 음(−) |
| **H2′ 문구효과** | 매파 문구가 부정으로 점수화 | `DGS2` 음(−), `DFF` 음(−) |
| **H3 물가** | 부호 불명 — 낙관과 인플레 기대의 관계는 국면 의존 | `T5YIE`·`MICH` 예측 없음 |

H2 와 H2′ 는 정면으로 대립하며, **어느 쪽이 지지되든 그 자체가 결과다.** 프로젝트의 알려진 한계(감성≠정책스탠스)를 정면으로 검정하는 셈이다. H3 는 정직하게 "예측 없음"으로 등록한다 — 억지 예측을 다는 것보다 낫다.

### 판정 기준

부호가 아니라 **다음 조건이 성립하는가**가 판정이다:

```
|corr(통합, 지표)| > max(|corr(Fed, 지표)|, |corr(News, 지표)|)
```

부호가 어느 쪽이든 통합이 각 축을 이기면 50:50 의 근거가 선다. 8개 지표 중 **몇 개에서 성립하는가**의 일관성으로 결론을 낸다.

### [2026-08-09 구현 중 추가] 우위폭 Δ 의 유의성 검정

위 부등식은 **점추정 비교**일 뿐이라 "우위가 우연과 구분되는가"를 답하지 못한다.
통합 상관의 부트스트랩 CI 역시 "통합 상관이 0 이 아니다"만 말한다 — 이 항목의 주장과
검정이 어긋난다. 그래서 우위폭 자체를 부트스트랩하는 검정을 추가했다:

```
Δ = |corr(통합)| - max(|corr(Fed)|, |corr(News)|)
```

Δ 의 95% CI 하한이 0 을 넘어야 우위를 주장한다. 구현: `validate_weights.boot_delta_ci()`.
`max()` 가 들어가 CI 가 아래로 치우치는 편향이 있어 **보수적** 검정이다(없는 우위를
만들어내지는 않는다). 결과는 `docs/weight_validation.md` §7 참조 — 이 검정을 적용하니
기존 문서의 "뚜렷하게 낫다"는 서술이 지지되지 않았다.

## 5. 표본·정렬 규칙

### 5-1. 기준 표본

**2000-02 ~ 2021-05, 월간 256개월** — 기존 VIX 검증(`headline_norm.json`)과 **동일 구간**을 쓴다. 수치를 나란히 놓고 비교할 수 있어야 하기 때문이다.

이 구간이 상한인 이유는 뉴스 축의 구조 때문이다:

| 뉴스 축 | 소스 | 범위 | 규모 |
|---|---|---|---|
| 과거 백본 | WSJ (ProQuest) | 2000-01 ~ 2021-12 | 38,869건 (월별) |
| **공백** | — | **2022-01 ~ 2026-06** | 0건 |
| 라이브 | Marketaux | 2026-07-03 ~ | 947건 (일별) |

**라이브 구간(37일)은 검증에 쓰지 않는다.** `UNRATE`·`INDPRO`·`MICH` 는 월간이라 관측치가 1~2개, 일간 계열도 거래일 25개 남짓이다. 숫자는 나오지만 의미가 없다. 라이브는 **배관 점검용**(수집→지수→상관 파이프가 도는지)으로만 쓴다.

2022~2026 공백은 **메우지 않는다**(팀 결정). WSJ 전문은 ProQuest 스크레이핑으로 모은 것이라 크롤링 금지 지시 하에서는 같은 방식으로 확장할 수 없다. 공백 해소는 별도 과제로 분리한다.

### 5-2. 감성지수 축 구성 (기존 방식 그대로 재사용)

`build_headline_norm.py` 와 동일하게 만든다. 새로 정의하지 않는다:

- **Fed 축**: `meetings` 테이블 `method='conf_weighted'` → 월 그리드 `resample("MS").last().ffill()` (회의 없는 달은 직전값 이월)
- **News 축**: `outputs/news_index.csv` 의 월별 `conf_weighted`
- **통합**: 각 축 전체 구간 mean/std 로 z 표준화 후 `0.5*fz + 0.5*nz`

### 5-3. 지표 변환 (중요)

기존 VIX 검증은 **수준(level) 상관**이었다. VIX 는 평균회귀 계열이라 수준으로 써도 됐지만, 새 패널에는 추세가 강한 계열이 섞여 있다. 추세 계열끼리 수준 상관을 내면 **허위상관(spurious correlation)** 이 나온다.

지표별로 다음과 같이 처리하고, **수준·변화 두 결과를 모두 보고**한다. 기존 -0.534 와의 비교 가능성(수준)과 통계적 타당성(변화)을 둘 다 지키기 위해서다.

| 지표 | 변환 | 주 판정 | 사유 |
|---|---|---|---|
| `NFCI` | 수준 / Δ | **수준** | 이미 표준화된 정상 계열 (평균 0) |
| `T5YIE` | 수준 / Δ%p | **수준** | 기대인플레는 평균회귀적 |
| `MICH` | 수준 / Δ%p | **수준** | 동일 |
| `UNRATE` | 수준 / Δ%p | **변화** | 수준에 순환적 추세 |
| `DGS2` | 수준 / Δ%p | **변화** | 2000~2021 장기 하락 추세 |
| `DFF` | 수준 / Δ%p | **변화** | 동일 |
| `INDPRO` | 로그차분 | **변화** | 명확한 성장 추세 — 수준 상관 무의미 |
| `WALCL` | 로그차분 | **변화** | QE 로 인한 강한 단조 증가 |

`INDPRO`·`WALCL` 은 수준 결과를 아예 싣지 않는다 (해석 불가능한 숫자를 표에 넣지 않는다).

변화 모드에서는 감성지수 쪽도 동일하게 전월대비 차분(Δ)을 취한다.

### 5-4. 주기 정렬

일간·주간 계열(`T5YIE`, `DGS2`, `DFF`, `WALCL`, `NFCI`)은 **월평균**으로 집계한다. 기존 VIX 처리(`resample("MS").mean()`)와 동일하다.

## 6. 구현

### 6-1. 신규 모듈

| 파일 | 역할 |
|---|---|
| `analysis/collect_macro.py` | FRED 8계열 일괄 수집 → `outputs/macro_monthly.csv` (월별 정렬·변환 포함) |
| `analysis/validate_weights.py` | 지표별 Fed/News/통합 상관표 생성 → `outputs/weight_validation.csv` |
| `docs/weight_validation.md` | 가설·결과·판정. 팀원 인계 문서 |

`market` 테이블 스키마는 **건드리지 않는다.** 스키마 변경은 팀 합의 사안이라(README 명시) 별도 CSV 로 시작한다. 나중에 정착하면 그때 스키마 편입을 제안한다.

### 6-2. 데이터 흐름

```
FRED 공개 CSV (8계열)
    ↓ collect_macro.py  — 다운로드 · 월별 집계 · 변환(수준/차분)
outputs/macro_monthly.csv
    ↓
    ├── data/fomc.db (meetings, conf_weighted) ──┐
    └── outputs/news_index.csv ──────────────────┤
                                                  ↓ validate_weights.py
                                    z표준화 → 0.5:0.5 결합 → 지표별 상관
                                                  ↓
                              outputs/weight_validation.csv + docs/weight_validation.md
```

### 6-3. 모듈 경계

- `collect_macro.py` 는 **수집·정렬만** 한다. 상관을 모른다. 입력은 (계열 ID, 기간), 출력은 월별 DataFrame/CSV. 단독 테스트 가능.
- `validate_weights.py` 는 **분석만** 한다. FRED 를 모른다. 입력은 감성 축 2개 + 지표 DataFrame, 출력은 상관표. 지표가 늘어도 이 모듈은 안 바뀐다.
- 두 모듈 다 `headline.py` 의 결합 로직을 재구현하지 않고 **호출한다** (`combine()` 또는 동일 z 공식). 결합 방식이 두 곳에 존재하면 반드시 어긋난다.

### 6-4. 기존 자산 재사용

`analysis/validate_robustness.py` 에 홀드아웃·블록부트스트랩·LOMO 가 이미 구현돼 있다(VIX 기준). **지표만 주입 가능하도록 파라미터화**하면 새 패널에 그대로 적용된다. 새로 짜지 않는다.

### 6-5. 산출물 형식

`outputs/weight_validation.csv` — **아래 숫자는 열 구조를 보이기 위한 가상 예시이며 실제 결과가 아니다**:


## 8. 한계 · 리스크

- **다중비교**: 8개 지표 × 최대 2변환 = **14개 조합**(`INDPRO`·`WALCL` 은 변화만)을 보면 하나쯤은 우연히 좋게 나온다. 개별 유의성이 아니라 **전 지표에 걸친 일관성**으로 판정하고, **모든 결과를 싣는다.** 체리피킹 금지.
- **자기상관**: 월별 감성 축은 자기상관이 강하다(특히 Fed 축은 회의 없는 달 `ffill` 이라 계단 함수). 단순 p값은 과대평가된다 → 블록 부트스트랩 CI 를 주 근거로 쓰고, 단순 p값은 참고로만 싣는다.
- **Fed 축 이월(ffill)**: 기존 방식을 그대로 따르지만, 이게 인위적 지속성을 만든다는 점은 문서에 남긴다. 변경하면 기존 수치와 비교가 깨지므로 이번 범위에서는 바꾸지 않는다.
- **부호 방향의 이론적 모호성**: H2 vs H2′ 가 미해결이다. 결과가 갈리면 그대로 보고하고 해석은 스토리텔링 담당자와 함께 정한다.
- **뉴스 축 단일 소스**: WSJ 한 매체라 매체 편향이 남는다. 기존 문서(`news_fed_index.md`)에 이미 기록된 한계이며 이번 작업으로 해소되지 않는다.
- **음성 결과 가능성**: 통합이 각 축을 못 이기는 지표가 다수일 수 있다. **그 경우에도 그대로 보고한다.** 50:50 은 지도교수 지시이므로 유지하되, "VIX 외 지표에서는 근거가 약하다"고 정직하게 쓴다.

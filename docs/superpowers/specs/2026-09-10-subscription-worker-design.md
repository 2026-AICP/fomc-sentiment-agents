# 구독 접수 창구 — Cloudflare Worker + KV 설계

> 작성일: 2026-09-10 · 상태: 설계 확정 (구현 전)
> 상위 설계: `docs/notification_design.md` §6 (인프라) · §1 (범위)
> 미결 항목: `docs/notification_open_decisions.md` A-1 · A-3

---

## 1. 배경 — 왜 지금인가

2026-09-10 에 발송 인프라가 완성됐다.

| | |
|---|---|
| 도메인 | `econpilot.org` — Cloudflare Registrar |
| 메일 인증 | Resend Verified (SPF · DKIM · DMARC 공개 DNS 확인) |
| 키 | `RESEND_API_KEY` — GitHub Actions Secret |
| 발송 확인 | 예열 3통 실발송 성공 (`.github/workflows/warmup-email.yml`) |

**그런데 보낼 대상이 없다.** 구독 접수 창구가 없어 명단 자체가 존재하지 않는다.
알림 판정(`agents/notifier.py`)은 드라이런으로 매일 돌고 있으나, 판정 결과가
누구에게도 가지 않는다.

이 문서는 그 빈칸 — **명단을 만들고 보관하고 읽는 경로** — 를 설계한다.

### 조교님 순서와의 관계

조교님 답변(2026-09-10)은 실제 발송을 켜기 전 순서를 못 박았다.

```
① 뉴스 필터·M그룹 키워드 확정 → ② 백필 재생성 → ③ z-파라미터 재추정
→ ④ θ 재보정 → ⑤ 그 이후 실제 알림을 켠다
```

**구독 창구는 이 순서와 독립이다.** ①~④는 "무엇을 보낼지"를 정하고, 이 문서는
"어디로 보낼지"를 정한다. 병렬로 진행해 ④가 끝났을 때 대기 시간이 없게 한다.

## 2. 범위

**만든다**

- 구독 접수 · 확인 · 해지 엔드포인트 (Cloudflare Worker)
- 구독자 저장소 (Cloudflare KV)
- GitHub Actions 가 명단을 읽는 경로

**만들지 않는다**

- 구독 폼 UI — 대시보드 쪽 작업이고 A-3(위치)이 미결이다
- 실제 알림 발송 코드 — `agents/notifier.py` 는 손대지 않는다.
  드라이런과 `tests/test_notifier_node.py` 의 "발송 모듈 import 금지" 잠금을
  그대로 둔다. 발송은 ⑤ 단계다
- 웹푸시 — `docs/notification_design.md` §1 대로 설계만 두고 구현하지 않는다.
  다만 레코드에 `channel` 필드는 처음부터 넣는다

## 3. 더블 옵트인은 하지 않는다 — §6-3 그대로

`docs/notification_design.md` §6-3 의 판단을 유지한다.

> 타인 주소 무단 등록을 막는 정석이지만, 확인 플로우를 더 만들어야 하고 학부
> 프로젝트 규모에는 과하다. 대신 수신거부를 한 번 클릭으로 끝나게 해 오등록
> 피해를 최소화한다.

주소를 입력하면 즉시 명단에 들어간다. 확인 메일 단계가 없다.

### 그래서 상쇄 장치가 실제로 작동해야 한다

확인 절차가 없으면 **누구나 남의 주소를 등록할 수 있다.** 그 사람이 원치 않는
메일을 받고 [스팸 신고]를 누르면 그 신호는 `econpilot.org` 도메인에 남는다.
§6-3 이 "원클릭 수신거부로 상쇄한다"고 한 부분이 말로 그치면 안 되는 이유다.

세 가지로 상쇄한다.

**1. 가입 즉시 환영 메일을 보낸다.** 오등록된 사람이 자기가 등록됐다는 사실을
그 자리에서 알고 바로 해지할 수 있어야 한다. 이 메일이 없으면 오등록된 사람은
**첫 알림이 올 때까지 모른다** — 그때는 이미 늦다.

**2. 모든 메일에 `List-Unsubscribe` 헤더를 넣는다.** Gmail·Outlook 이 메일 상단에
해지 버튼을 띄워준다. **스팸 신고 버튼 바로 옆에 해지 버튼이 있으면 사람들은
해지를 누른다.** 우리에게 훨씬 덜 아픈 쪽이다.

**3. 해지는 즉시 삭제한다.** 보관하지 않는다 (§6-3).

즉 여기서 요청 제한(§7)이 유일한 사전 방어선이 된다. 더블 옵트인이 있었다면
봇이 넣어도 명단에 안 들어왔겠지만, 지금 설계에서는 **넣는 즉시 들어온다.**

## 4. 데이터 모델 (KV)

키 종류는 셋이다.

| 키 | 값 | TTL |
|---|---|---|
| `sub:<sha256(email)>` | 구독 레코드 (아래) | 없음 |
| `tok:<해지토큰>` | `sha256(email)` | 없음 |
| `rate:<ip>` | 분당 요청 수 | 60초 |

구독 레코드는 `docs/notification_design.md` §6-1 스키마를 그대로 쓴다.

```json
{
  "id":          "uuid",
  "channel":     "email",
  "email":       "someone@example.com",
  "level":       "alert",
  "fed_events":  true,
  "overnight":   true,
  "created_at":  "2026-09-10T00:00:00Z",
  "unsub_token": "..."
}
```

### 왜 이메일을 해시해 키로 쓰나

키 목록(`list`)만 조회해도 주소가 전부 보이는 상황을 막는다. 값을 열어야만
주소가 나온다. Cloudflare 계정을 팀 4명이 공유하므로 실수 경로를 하나 줄인다.

부수 효과로 **중복 가입이 자동 처리된다** — 같은 주소는 같은 해시라 덮어써진다.

### 왜 `tok:` 역인덱스가 따로 필요한가

해지 링크에는 해지 토큰만 들어 있고 이메일은 없다. 토큰에서 레코드를 찾으려면
역인덱스가 있어야 한다. **링크에 이메일을 넣지 않는 이유**는 그 주소가 메일
본문·브라우저 주소창·서버 로그에 그대로 남기 때문이다.

## 5. 엔드포인트

Worker 는 `econpilot.org/api/*` 로 라우팅한다 (`*.workers.dev` 가 아니다).
**수신거부 링크가 메일 발신 도메인과 같아야** 받는 쪽에서 낯선 링크로 보이지
않고 스팸 필터에도 유리하다.

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| `POST` | `/api/subscribe` | 명단 등록 + 환영 메일 |
| `GET` | `/api/unsubscribe?t=` | 확인 페이지만 표시. **삭제하지 않는다** |
| `POST` | `/api/unsubscribe` | 실제 삭제 |
| `GET` | `/api/export` | 명단 반환 (Bearer 인증) |

### 5-1. 구독 흐름

```
[폼] POST /api/subscribe {email, level}
        │
        ├─ 요청 제한 초과 → 429
        ├─ 이메일 형식 검증 실패 → 400
        ├─ Resend 로 환영 메일 발송 (해지 링크 포함)
        │     └─ 실패하면 → 502, **아무것도 저장하지 않는다**
        ├─ sub:<hash> 저장 + tok:<해지토큰> 저장
        └─ 200 응답  ← "이미 가입된 주소인지"는 알리지 않는다
```

**메일을 먼저 보내고 성공했을 때만 저장한다 (2026-09-10 정정).** 초판은 순서가
반대였다. 그러면 저장과 발송 사이에 isolate 가 죽거나 롤백이 실패했을 때
**메일이 안 간 레코드**가 남는데, 아래에 적었듯 그건 이 설계가 막으려는 바로
그 상태다. 반대 방향의 실패(메일은 갔는데 저장 실패)는 무해하다 — 구독됐다고
들었지만 실제로는 아니고, 다시 신청하면 된다.

**가입 여부를 응답으로 알리지 않는 이유** — 알리면 임의의 주소를 넣어보며
"이 사람이 구독자인가"를 확인할 수 있다. 이미 있는 주소면 조용히 덮어쓰고
응답은 항상 같게 둔다.

**환영 메일은 선택이 아니다.** 확인 단계가 없으므로(§3), 오등록된 사람이
자기가 등록됐음을 아는 유일한 통로다.

### 5-2. 해지 — GET 하나로 끝내지 않는다

**Gmail·Outlook 은 메일 속 링크를 미리 열어보는 경우가 있다.** GET 에서 바로
삭제하면 구독자가 클릭하지도 않았는데 해지된다.

```
[메일 하단 링크] GET /api/unsubscribe?t=<토큰>
        └─ 확인 페이지 + [해지] 버튼   ← 아직 삭제 안 함

[버튼] POST /api/unsubscribe {token}
        ├─ tok:<토큰> → hash 조회
        ├─ sub:<hash> 삭제 + tok:<토큰> 삭제   ← 보관하지 않는다 (§6-3)
        └─ 완료 페이지
```

메일 앱의 해지 버튼용으로 `List-Unsubscribe` 헤더도 넣는다. 이때
`List-Unsubscribe-Post: List-Unsubscribe=One-Click` 을 함께 보내면
(RFC 8058) 메일 앱이 **POST** 로 호출하므로 프리페치 문제가 없다.

### 5-3. CORS

사이트는 `https://aicp-econpilot.github.io`, Worker 는 `econpilot.org` 라
교차 출처다. `Access-Control-Allow-Origin` 을 **그 주소 하나로 고정**하고
`OPTIONS` 프리플라이트를 처리한다. `*` 는 쓰지 않는다 — 남의 사이트가 우리
엔드포인트로 가입 요청을 보내게 된다.

**단, CORS 는 서버측 인증이 아니다.** 브라우저가 지키는 규칙이라 `curl` 이나
스크립트로 오는 요청은 그대로 통과한다. 공개 엔드포인트를 실제로 지키는 것은
더블 옵트인(§3)과 요청 제한(§7)이다. CORS 는 남의 웹페이지가 우리 창구를
자기 폼처럼 쓰는 것을 막는 정도로만 기대한다.

## 6. GitHub Actions 가 명단을 읽는 경로

Cloudflare API 토큰 대신 **Worker 의 인증된 `/api/export`** 를 쓴다.

| | Cloudflare API 토큰 | `/api/export` |
|---|---|---|
| 새 Secret | 2개 (토큰 + 계정 ID) | **1개** |
| 권한 범위 | KV 전체로 넓어지기 쉽다 | 이 용도 하나 |
| 유출 시 피해 | 계정의 KV 를 읽고 쓸 수 있다 | 명단을 읽을 수 있다 |

```
GET /api/export
Authorization: Bearer <SUBSCRIBERS_TOKEN>

200 → {"subscribers": [ <구독 레코드>, ... ], "count": N}
401 → 헤더가 없거나 값이 다를 때
```

토큰은 Worker 쪽에 `wrangler secret put`, Actions 쪽에 GitHub Secret 으로
같은 값을 둔다. 리포에는 넣지 않는다.

### 명단은 리포에 절대 커밋하지 않는다

`docs/notification_design.md` §6-3 ★ 의 원칙을 그대로 따른다. 리포가 PUBLIC 이고
히스토리는 되돌려도 남는다. **이 프로젝트는 산출물을 전부 리포에 커밋하는
구조라 자연스럽게 그 길로 갈 위험이 크다.** `/api/export` 응답은 러너 메모리에만
두고 파일로 쓰지 않는다.

## 7. 남용 방어

더블 옵트인을 하지 않으므로(§3) **요청 제한이 유일한 사전 방어선이다.**

- **같은 IP 분당 5회 제한** — KV 카운터(키 `rate:<ip>`, TTL 60초). 초과 시 429
- **이메일 형식 검증** — 명백한 쓰레기 입력을 거른다

Turnstile(캡차)은 지금 넣지 않는다. 구독 폼이 공개되는 시점(§9)에 봇 트래픽이
실제로 관측되면 그때 추가한다. **다만 확인 단계가 없는 설계라 캡차가 필요해질
가능성은 더블 옵트인이 있을 때보다 높다** — 폼 공개 후 KV 증가 추이를 한동안
지켜봐야 한다.

## 8. 파일 배치 · 배포 · 테스트

```
workers/subscribe/
  wrangler.toml
  src/index.js          라우팅 · CORS · KV 바인딩
  src/handlers.js       순수 함수 (KV·fetch 를 인자로 받는다)
  test/handlers.test.js
  README.md             배포 방법 · 시크릿 설정
```

**핸들러를 순수 함수로 분리한다.** KV 와 메일 발송을 인자로 받으면 테스트에서
`Map` 과 가짜 함수로 갈아 끼울 수 있다. Node 내장 `node:test` 로 돌려
새 의존성이 0 이다.

배포는 `npx wrangler deploy` **수동**으로 한다. 자동 배포는 지금 필요 없다.

### 성공 기준

구현이 끝났다고 말할 수 있는 조건이다.

1. `node --test workers/subscribe/test/` 전부 통과
2. 배포 후 실제 주소로 가입 → KV 에 레코드 1건 + 환영 메일 도착
3. 같은 IP 로 1분에 6번 요청하면 6번째가 429
4. 해지 링크 GET 은 삭제하지 않고, 버튼(POST)에서만 삭제된다
   해지 후 KV 에서 `sub:` 와 `tok:` 가 모두 사라진다
5. `/api/export` 가 Bearer 없이는 401, 있으면 명단 반환
6. 브라우저에서 `aicp-econpilot.github.io` 외의 출처로 호출하면 CORS 로 차단된다
   (스크립트 요청은 통과한다 — §5-3 참조)

## 9. 미해결 — 구현과 별개

**구독자 이메일 수집의 절차적 요건을 조교님께 확인하지 못했다.**
2026-09-10 답변 6건에 이 항목이 없다.

코드를 만드는 것은 무관하다. 다만 **폼을 실제로 공개해 외부인 주소를 받기
시작하는 것**은 답을 받은 뒤가 맞다. 만들어 두고 공개는 나중에 한다.

`A-3`(구독 UI 위치, 잠정 결정 B — 신호 탭 안)도 미결이다. 이 문서는 UI 를
만들지 않으므로 진행에 지장이 없다.

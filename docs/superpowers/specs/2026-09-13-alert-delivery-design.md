> 상위 설계: `docs/notification_design.md` · 구독 창구: `docs/superpowers/specs/2026-09-10-subscription-worker-design.md`

## 2. 결정 기록 (2026-09-13, 담당 판단)

**받는 사람은 팀 고정 명단과 구독자의 합집합이다.** 팀원은 설정 없이 받고, 교수님·
조교님·그 밖의 관심 있는 사람은 스스로 신청·해지한다.

**구독 폼은 대시보드 신호 탭에 공개한다.** 링크를 따로 돌리는 방식(Worker 전용
페이지)도 검토했으나, 누구든 쓸 수 있어야 한다는 판단으로 대시보드에 둔다. 팀이
잠정 결정한 구독 UI 위치(A-3 B안, 신호 탭 안)와 같다.

**외부인 주소 수집에 조교님 사전 확인을 받지 않는다.** 구독 창구 설계 §9 가 이것을
"폼 공개 전 조건"으로 남겨두었으나, 담당 판단으로 해제한다. 근거 — 신청자는 대부분
프로젝트 관계자이고 외부 관심자는 극히 적을 것이다. 대신 설계문서 §6-3 이 요구한
**수집 안내문을 폼에 명시**하는 것으로 갈음한다.

## 3. 범위

**만든다**
- `agents/mailer.py` — 명단 조회 · 개인별 발송 · 드라이런 스위치
- `agents/graph.py` 배선 — 판정이 `send` 인 결정마다 발송하고 결과를 로그에
- 대시보드 신호 탭 "알림 받기" 섹션 — 이메일 입력 + 수집 안내문 + 폼 스위치
- 워크플로 설정 — 시크릿·변수 전달

**만들지 않는다**
- ⚠️ 주의 구독 — B-2 미결. 폼에 등급 선택지를 두지 않는다
- 구독자별 FOMC 일정 수신 거부 UI — 레코드의 `fed_events` 는 발송 시 존중하지만,
  폼에서 끄는 선택지는 두지 않는다 (해지가 원클릭이다)
- 확인 메일(더블 옵트인) · 캡차 — 구독 창구 설계 §3 · §7 결정 그대로

## 4. 명단

```
recipients = 팀 고정 (GitHub Secret ALERT_RECIPIENTS, 쉼표 구분)
           ∪ 구독자 (GET https://econpilot.org/api/export, Bearer SUBSCRIBERS_TOKEN)
```

- 주소는 소문자·공백제거로 정규화해 겹치면 한 번만. **겹치면 팀 쪽이 이긴다** —
  팀원이 폼에서도 신청했더라도 팀 고정 수신자로 취급한다
- **Worker 조회가 실패해도 팀원에게는 보낸다.** 실패 사실은 파이프라인 로그에 남긴다.
  명단 조회 실패로 경고 메일 전체가 사라지는 것이 더 나쁘다
- 명단은 **러너 메모리에만 둔다.** 파일로 쓰지 않는다 — 리포가 PUBLIC 이다
  (구독 창구 설계 §6)

## 5. 발송

### 5-0. 무엇을 보내나

한 번의 실행에서 판정이 `send` 인 결정 네 종류가 발송 대상이다 — 일별 신호(`signal`) ·
FOMC 회의일(`fed_meeting`) · 정정(`correction`) · 회의록(`fed_minutes`). 억제된 결정
(`merged_same_day` 포함)은 보내지 않는다. 발신 주소는 Worker 환영 메일과 같은
`EconPilot <noreply@econpilot.org>` 다.

### 5-1. 개인별로 한 통씩

받는 칸에 여러 주소를 넣으면 **받는 사람끼리 주소가 보인다.** 교수님 주소가 구독자
전원에게 노출되는 사고를 막기 위해 한 명씩 보낸다. 월 1~3통 × 수십 명이라 Resend
무료 한도(하루 100통)에 걸리지 않는다.

Resend API 는 초당 요청 수 제한이 있으므로 수신자 사이에 짧은 간격(0.6초)을 둔다.

### 5-2. 푸터와 해지

| 수신자 | 메일 하단 | 헤더 |
|---|---|---|
| 구독자 | 본인 전용 해지 링크 `https://econpilot.org/api/unsubscribe?t=<unsub_token>` | `List-Unsubscribe` + `List-Unsubscribe-Post: List-Unsubscribe=One-Click` |
| 팀 고정 | "팀 고정 수신자입니다. 수신을 원치 않으면 팀에 알려주세요." | 없음 |

`notifier.render` 는 푸터 문구를 인자로 받는다. **인자가 없으면 지금의 드라이런 푸터를
그대로 쓴다** — 기존 동작과 테스트가 바뀌지 않는다.

### 5-3. 구독자 설정 존중

- 레코드의 `fed_events` 가 false 인 구독자에게는 `fed_meeting` · `fed_minutes` 를
  보내지 않는다. 신호·정정 메일에 합쳐진 일정(`fed_event` 표시)은 신호 메일이므로 보낸다
- `level` 은 지금 전원 `alert` 로 취급한다 (⚠️ 채널 미개방)

### 5-4. 실패 처리

- 수신자 한 명의 발송 실패는 **그 한 명만** 실패로 센다. 나머지는 계속 보낸다
- 발송 중 예상 못 한 예외가 나도 **파이프라인을 죽이지 않는다** — 수집 단계와 같은 원칙
- 일부 실패해도 그 알림은 "보냄"으로 기록한다. **재시도하지 않는다** — 받은 사람에게
  두 통이 가는 것보다 못 받은 사람이 생기는 쪽을 택한다. 실패 수는 로그에 남는다

---

## 6. 스위치 두 개

### 6-1. 발송 스위치 — `ALERT_SEND`

GitHub **Repository Variable**(Secret 아님)로 둔다. 켜고 끌 때 코드 커밋이 필요 없다.

```
ALERT_SEND = "1"   → 실제 발송
그 외 · 미설정      → 드라이런 (네트워크 호출 없음, 지금과 동일)
```

`notifier.py` 는 판정만 하고 발송 모듈을 import 하지 않는다는 잠금
(`tests/test_notifier_node.py`)은 **유지한다.** 발송은 `mailer.py` 에만 있다.

### 6-2. 폼 스위치 — 대시보드 상수

사이트는 deploy 브랜치를 외부 저장소가 빌드하므로, 머지하는 순간 공개된다. **Worker
배포 전에 폼이 보이면 신청이 전부 실패한다.** 그래서 폼은 소스 상수로 끄고 켠다.

```js
// dashboard-web/src/lib/data.js
export const SUBSCRIBE_OPEN = false;   // Worker 배포 확인 후 true
```

꺼져 있으면 섹션 자체를 그리지 않는다.

---

## 7. 로그

`append_log` 에 `channel` · 수신자 수 · 실패 수를 인자로 넘긴다. **인자가 없으면 지금처럼
드라이런 값**(`dryrun`, 0, 0)이다.

| | channel | n_recipients | n_failed |
|---|---|---|---|
| 드라이런 | `dryrun` | 0 | 0 |
| 실제 발송 | `email` | 보낸 인원 | 실패 인원 |

개인 식별 정보는 여전히 어떤 컬럼에도 없다 — 수신자는 "수"뿐이다.

로그를 쓰는 시점을 **발송 뒤로** 옮긴다. 수신자 수를 알아야 기록할 수 있다.

## 8. 대시보드 "알림 받기" 섹션

신호 탭 맨 위, "네 가지 규칙" 앞에 둔다 — 탭에 들어온 사람이 가장 먼저 본다.

```
알림 받기
경고 신호와 FOMC 일정(연 약 16회)을 이메일로 보내드립니다.

[ 이메일 주소            ] [신청]

수집하는 정보  이메일 주소 1개
사용 목적      알림 발송
보관 기간      프로젝트 종료 시 전량 삭제
해지          모든 메일 하단 링크로 즉시 해지 · 해지 시 주소 즉시 삭제
참고용이며 투자조언이 아닙니다.
```

Worker 응답과 문구를 1:1 로 맞춘다.

| Worker 응답 | 화면 문구 |
|---|---|
| 200 | 신청되었습니다. 환영 메일을 확인해주세요 (스팸함도 확인) |
| 400 | 이메일 주소를 확인해주세요 |
| 429 | 잠시 후 다시 시도해주세요 |
| 502 | 메일 발송에 실패했습니다. 잠시 후 다시 시도해주세요 |
| 네트워크 오류 | 연결에 실패했습니다 |

**이미 가입된 주소인지는 알리지 않는다** — Worker 가 항상 200 을 준다
(구독 창구 설계 §5-1).

## 9. 남용 방어

확인 메일도 캡차도 없고 폼이 공개되므로 **요청 제한이 유일한 사전 방어선이다.**

- Worker 코드의 IP 분당 5회 제한은 KV 캐시 특성상 실제로 막히는지 배포 후 확인이
  필요하다 (최종 리뷰 I3)
- **폼을 켜기 전에 Cloudflare 대시보드에서 `econpilot.org/api/subscribe` 에 요청 제한
  규칙을 건다.** 이것이 실제 관문이다
- 봇 가입이 관측되면 캡차를 추가한다

## 10. 워크플로

`.github/workflows/daily-news.yml` job env 에 추가한다.

```yaml
RESEND_API_KEY:    ${{ secrets.RESEND_API_KEY }}      # 이미 등록됨
ALERT_RECIPIENTS:  ${{ secrets.ALERT_RECIPIENTS }}    # 신규 — 팀 주소
SUBSCRIBERS_TOKEN: ${{ secrets.SUBSCRIBERS_TOKEN }}   # 신규 — Worker 와 같은 값
ALERT_SEND:        ${{ vars.ALERT_SEND }}             # 신규 — 스위치
```

크론은 main 의 워크플로 파일을 쓰고 작업은 deploy 를 체크아웃하므로 **양쪽 브랜치에
같이 반영**한다.

## 11. 성공 기준

1. `ALERT_SEND` 미설정 시 네트워크 호출 0건, 로그는 지금과 동일 (`dryrun`, 0)
2. `ALERT_SEND=1` 이면 판정이 `send` 인 알림마다 수신자 1명당 1통, 로그 `email`
3. 받는 사람끼리 주소가 보이지 않는다 (요청 1건당 수신자 1명)
4. 구독자 메일에만 해지 링크와 `List-Unsubscribe` 헤더가 있다
5. Worker 조회 실패 시에도 팀원에게는 발송된다
6. 수신자 1명 발송 실패가 나머지와 파이프라인을 멈추지 않는다
7. `fed_events=false` 구독자는 FOMC 일정 알림을 받지 않는다
8. `SUBSCRIBE_OPEN=false` 면 폼이 그려지지 않는다
9. 실제 발송 시험 — 형준 1명에게 수동 실행으로 도착 확인

## 12. 순서

```
1. 구현 + 리뷰            두 스위치 모두 꺼진 채로 main·deploy 머지
2. 형준                   Worker 시크릿 2개 등록 · 배포
                          GitHub Secret ALERT_RECIPIENTS · SUBSCRIBERS_TOKEN 등록
                          Cloudflare 요청 제한 규칙
3. 시험 발송              ALERT_RECIPIENTS 를 형준 1명으로 두고 수동 실행
4. 팀 명단으로 교체 · ALERT_SEND=1
5. SUBSCRIBE_OPEN=true
```

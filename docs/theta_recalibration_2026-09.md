## 0. 결론 먼저

θ 세트가 둘인데 **결론이 반대**다.

| | 현재 값 | 실측 분위수 | 부트스트랩 95% CI | 판정 |
|---|---|---|---|---|
| **COMBINED** `theta_shift` | 0.95 | 1.106 | [0.804, **1.545**] | **유지** — CI 안 |
| **COMBINED** `theta_t` | 0.22 | 0.227 | [0.192, 0.305] | **유지** — CI 안 |
| **DEFAULT** `theta_shift` | 0.10 | 0.251 | [0.207, 0.301] | **바꿔야 함** — CI 밖 |
| **DEFAULT** `theta_t` | 0.05 | 0.114 | [0.082, 0.133] | **바꿔야 함** — CI 밖 |

**COMBINED 가 어긋나 보이던 것은 θ 문제가 아니라 z 문제였다.** z-파라미터를
바로잡으면 현재 θ 가 저절로 맞는다. **DEFAULT 는 z 와 무관한 별개 원인**
(T=3.1 → T=1 전환)이고 실제로 어긋나 있다.

## 1. COMBINED — z 를 고치면 θ 는 그대로 맞다

`agents/graph.py` 가 쓰는 일별 알림용 θ 다.

### 무엇이 문제였나

`theta_shift = 0.95` 의 발동률이 설계 의도(~15%)의 3배였다. 원인을 θ 로 보고
재보정하려 했으나, **눈금(z-파라미터)이 틀린 위에서 재고 있었던 것**이다.

뉴스 축 z-파라미터가 WSJ **월별**(mean 0.0167 · std 0.0924) 인데 Marketaux
**일별** 에 적용되고 있었다. 주별 백필(BBD+HRS 확정 키워드, 298주)로 재추정한
값은 mean 0.0822 · std 0.1660 이다.

### 같은 θ, 다른 z

라이브 2026-07-10~09-10 (63일). 7/3~7/9 은 제외했다 — 기사 중앙값 3건으로
수집 초기 부실 표본이고, `export_dashboard.py` 의 `NEWS_LIVE_FROM` 이 이미
같은 이유로 제외하고 있다.

| | 현재 z (월별 WSJ) | **신규 z (주별 백필)** |
|---|---|---|
| 결합 지수 범위 | -3.39 ~ +2.63 | **-1.96 ~ +1.39** |
| \|z\| > 3 인 날 | 1일 | **0일** |
| `theta_shift=0.95` 발동률 | **46.8%** | **19.4%** |
| `theta_t=0.22` 차단률 | 9.5% | **23.8%** (설계 25%) |

**z 만 바꿨는데 발동률이 46.8% → 19.4% 가 된다.** θ 는 건드리지 않았다.

### 그래서 유지한다

| | 현재 | 이 분포의 분위수 | 차이 |
|---|---|---|---|
| `theta_t` | 0.22 | p25 = 0.227 | 3% |
| `theta_shift` | 0.95 | p85 = 1.106 | 16% |

둘 다 부트스트랩 95% CI 안이다. **"새 데이터가 다른 값을 요구한다"고 말할 수
없다.** n=62 에서 p85 의 CI 는 [0.804, 1.545] 로 두 배 가까이 벌어져 있어,
1.106 으로 바꾸는 것은 잡음을 쫓는 일이다.

민감도도 같은 방향을 가리킨다. `theta_shift` 는 배율 1.0~1.5 구간에서
11~19% 로 완만하고, 0.75 아래로 급격히 무너진다 — 현재 값은 평평한 구간의
초입에 있다.

| 배율 | 0.5 | 0.75 | **1.0** | 1.25 | 1.5 | 2.0 |
|---|---|---|---|---|---|---|
| θ_shift 발동률 | 54.8% | 37.1% | **19.4%** | 12.9% | 11.3% | 4.8% |

**2000-2021 월별 분포에서 나온 값이 2026 일별 분포의 CI 안에 들어온다는 것은
우연이 아니라 방법(분위수)이 맞았다는 증거다.** 바꾸지 않는 편이 더 강한 주장이다.

### 다만 `theta_t` 는 한계를 적어둔다

CI 안이지만 **민감하다**. 배율 0.5~2.0 에서 차단률이 6.3% → 54.0% 로 9배
움직인다. `docs/gate_sensitivity.md` 가 `ci_max` 에 내린 판정과 같은 부류다 —
"방어 가능한 값"이 아니라 "결론을 좌우하는 값"이다. 지금 바꿀 근거는 없으나
표본이 쌓이면 다시 볼 항목으로 남긴다.

## 2. DEFAULT — 이쪽은 실제로 어긋나 있다

`analysis/export_dashboard.py:61` 이 θ 를 넘기지 않아 이 값이 쓰인다. 즉
**공개 사이트의 "최근 회의 신호" 등급이 이 θ 로 매겨진다.**

대상 계열은 회의별 톤이다 (`dashboard-web/public/data/alerts.json`,
2000-02 ~ 2026-07, **221 회의**).

| | 현재 | 실측 분위수 | 발동/차단률 | 설계 의도 |
|---|---|---|---|---|
| `theta_shift` | 0.10 | **p85 = 0.251** | **45.9%** | ~15% |
| `theta_t` | 0.05 | **p25 = 0.114** | 11.8% 차단 | 25% |

**둘 다 부트스트랩 CI 밖이다.**

```
|Δ톤| p85 = 0.251   95% CI [0.207, 0.301]   현재 0.10 → CI 밖
|톤|  p25 = 0.114   95% CI [0.082, 0.133]   현재 0.05 → CI 밖
```

COMBINED 와 달리 n=220 이라 추정이 단단하다. **"바꿀 근거가 없다"가 아니라
"바꿔야 한다"** 고 말할 수 있는 유일한 경우다.

### 원인 — z 가 아니라 T 전환

이 계열에는 z-표준화가 없다. 원인은 2026-08-03(`8240208`)의 T=3.1 → T=1
전환이다. 톤 척도 자체가 약 2.2배 넓어졌는데 θ 가 따라가지 않았다.

| | 2026-07-03 문서값 (T=3.1) | 실측 (T=1) |
|---|---|---|
| \|톤\| p25 | 0.056 | **0.112** |
| \|Δ톤\| p85 | 0.097 | **0.228** |

`signal_calibration.md` §3 이 "`theta_t` = \|톤\| p25 ≈ 0.056 과 일치"라고
적은 근거가 지금은 성립하지 않는다.

### 눈에 보이는 결과

221 회의의 등급 분포에서 **⚠️ 주의가 89건으로 가장 많다.** 문턱이 낮아
주의가 기본 등급처럼 되어 있다.

```
⚠️ 주의  89   🟢 정합  58   🔴 경고  47   ⚪ 중립  27
```

### 제안값

원 보정과 **같은 방법**(분포 분위수)을 새 분포에 다시 적용한다. 새 방법을
만들지 않는다.

```
theta_shift  0.10 → 0.251   (p85, 발동률 45.9% → 15.0%)
theta_t      0.05 → 0.114   (p25, 차단률 11.8% → 24.9%)
```

민감도상 `theta_shift` 는 배율 2.0~3.0 에서 20.5% → 10.9% 로 비교적 완만하고
제안값(2.51배)이 그 안에 있다.

## 3. 적용 원칙 — 소급하지 않는다

`analysis/signals.py:43-48` 에 이미 적혀 있는 규칙이다.

> 새 θ 는 **적용 시작일(경계일) 이후에만** 쓴다. 이미 기록된 과거 등급을 새 θ 로
> 다시 매기지 않는다. 바꿀 때 이전 값과 경계일을 남길 것.

근거는 `docs/notification_design.md` §9. **과거 등급을 다시 매기면 "기준을
바꿔 성적을 좋게 만들었다"가 된다.**

DEFAULT 를 바꾸면 대시보드의 과거 221 회의 등급이 통째로 달라진다. 이건
소급 금지의 정면 사례이므로, **바꾸기 전에 경계일 처리 방침을 먼저 정해야 한다.**
θ 값 자체보다 이쪽이 큰 결정이다.

## 4. 아직 안 한 것

- **z-파라미터 적용.** 이 문서는 새 z 로 **계산만** 했고 `headline_norm.json`
  은 건드리지 않았다. 적용은 뉴스 축 담당 몫이다.
- **표준화 형태.** 팀 내부에서 n 기반 이분산 표준화
  (`Var = 0.0008 + 0.4629/n`)가 제안됐다. 고정 mean/std 를 바꾸는 것이라
  조교님 판단이 필요하고, 그 결과에 따라 §1 수치가 다시 움직인다.
- **DEFAULT 경계일 방침** (§3).
- **`theta_m`·`theta_vix`·`theta_rate`** 는 검토하지 않았다. 시장 척도라
  톤 척도 변경의 영향을 받지 않는다.

## 5. 한계

- **COMBINED 는 n=62 다.** p85 의 CI 가 [0.804, 1.545] 로 넓다. "바꿀 근거가
  없다"는 "바꾸면 안 된다"가 아니라 **"지금 데이터로는 판단할 수 없다"** 에 가깝다.
- 라이브 63일 구간의 뉴스축 참신호가 백필보다 뚜렷이 작다는 관측이 있다
  (버킷 경계에 따라 0.03~0.12, 백필 0.20). 조용한 구간의 분포로 문턱을 잡으면
  실제보다 낮게 잡힐 수 있다. 백필 5.5년에는 COVID·인플레 국면 전환이 들어 있다.
- 회의별 계열 221건은 2000~2026 전 구간이라 국면이 섞여 있다. 구간별 분위수
  차이는 보지 않았다.

## 6. 재현

```bash
# COMBINED — 새 z 로 결합 지수 재구성 후 분위수
python - <<'PY'
import pandas as pd
d = pd.read_csv('outputs/daily_headline.csv', parse_dates=['date'])
d = d[d.date >= '2026-07-10']
nz = (d.news - 0.0822) / 0.1660          # 주별 백필 파라미터
h = 0.5 * d.fed_carry + 0.5 * nz
print('theta_t  후보 p25 :', round(h.abs().quantile(.25), 3))
print('theta_sh 후보 p85 :', round(h.diff().abs().dropna().quantile(.85), 3))
PY

# DEFAULT — 회의별 계열 분위수
python - <<'PY'
import pandas as pd, json
a = pd.DataFrame(json.load(open('dashboard-web/public/data/alerts.json', encoding='utf-8')))
t = a.tone.abs().dropna(); dt = a.tone.diff().abs().dropna()
print('theta_t  후보 p25 :', round(t.quantile(.25), 3))
print('theta_sh 후보 p85 :', round(dt.quantile(.85), 3))
PY
```

주별 백필 파라미터는 `outputs/news_index_backfill_weekly.csv` 의
`conf_weighted` 평균·표준편차다.
